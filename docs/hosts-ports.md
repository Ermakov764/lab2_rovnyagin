# Hosts, IP and ports

Актуальные **IP/порты** для схемы `hl03 / hl11 / hl12`. **Пароли** храните в **`.env`** и не коммитьте.

---

## 0. Кто где и зачем

| Роль | Имя ВМ | IP (пример) | Порты (снаружи) | Зачем |
|------|--------|-------------|-----------------|--------|
| **CRUD + Additional** | **hl03** | **10.60.3.33** | **8080** CRUD, **8081** Additional | k6 бьёт в `http://10.60.3.33:8080`. |
| **PostgreSQL** | **hl12** | **10.60.3.9** (с сети); **127.0.0.1** (только с hl12) | **5433** -> в контейнере **5432** | JDBC с hl03: `DBHOST`/`DBPORT`. |
| **k6** | **hl11** | *см. `hostname -I`* | — | Нагрузка и графики, CRUD не поднимают. |

Проверка с hl11: `curl -sS -o /dev/null -w '%{http_code}\n' http://10.60.3.33:8080/actuator/health`

---

## 1. PostgreSQL: откуда как подключаться (psql / JDBC)

На **hl12** Postgres в Docker проброшен как **`0.0.0.0:5433 -> 5432`**. Для клиентов используйте **внешний порт хоста** (обычно **5433**), а не `5432`.

| Откуда вы подключаетесь | Host | Port | База (пример) | Пользователь |
|-------------------------|------|------|---------------|--------------|
| **Сам hl12** (psql на ВМ) | **`127.0.0.1`** | **5433** | **hl3** | **postgres** |
| **hl03** (приложение / `psql` / проверка) | **`10.60.3.9`** | **5433** | **hl3** | **postgres** |
| **Внутри Docker на hl03** (`crud-app`) | **`10.60.3.9`** | **5433** | **hl3** | то же, что в `.env` |

**Пароль** для `postgres` должен совпадать с **`SPRING_DATASOURCE_PASSWORD`** на hl03 и с настройкой образа на hl12 (в курсе часто отдельный пароль, не путать с pgAdmin). Если видишь **`FATAL: password authentication failed for user "postgres"`** — неверный пароль или не та БД/роль.

**Рабочий пример с hl12** (пароль возьми из `.env` / памятки курса):

```bash
PGPASSWORD='…' psql -h 127.0.0.1 -p 5433 -U postgres -d hl3
```

**С hl03** (если нет `psql`: `sudo apt install postgresql-client` или одноразово):

```bash
docker run --rm -e PGPASSWORD='…' postgres:15-alpine psql -h 10.60.3.9 -p 5433 -U postgres -d hl3 -c 'SELECT current_database();'
```

Если где-то встречается `localhost:5432`, это обычно другой контекст (подключение изнутри контейнера или локальная установка). С **хоста hl12** к Docker-Postgres обычно подключаются к **`127.0.0.1:5433`**.

## 3. `.env` на hl03 (с БД на hl12)

| Параметр | Пример | Комментарий |
|----------|--------|-------------|
| **`DBHOST`** | `10.60.3.9` | Не `localhost` hl03 и не `postgresdb`, если БД на hl12. |
| **`DBPORT`** | `5433` | Внешний порт публикации на **hl12**. |
| **`DBNAME`** / **`SCHEMANAME`** | `hl3` | Должны существовать на сервере. |
| **`SPRING_DATASOURCE_*`** | см. `.env` | = учётка Postgres на hl12. |

JDBC: `jdbc:postgresql://10.60.3.9:5433/hl3?currentSchema=hl3`

## 5. БД не подключается — коротко

1. **`DBPORT`** на hl03 = порт публикации на **hl12** (часто **5433**, не 5432).  
2. С hl03: `nc -zv 10.60.3.9 5433` или `pg_isready -h 10.60.3.9 -p 5433`.  
3. С hl12: `psql -h 127.0.0.1 -p 5433 …` — удобно отлаживать пароль/БД без сети.  
4. Логи: `docker compose -f docker-compose.hl12.yml logs crud-app --tail 120`

## 6. pgAdmin: вход и подключение сервера

**Где живёт pgAdmin:** на узле БД (обычно **hl12**) в отдельном DB-стеке курса.  
В этой ветке compose-файл DB-узла не хранится; `docker-compose.hl12.yml` на hl03 поднимает только `crud-app` и `additional-app`.

**Открыть в браузере**

- На **самой hl12:** `http://127.0.0.1:<ПОРТ>`  
- Число порта смотри в **`.env` на hl12:** переменная **`PGADMIN_PUBLISH_PORT`** (в репо по умолчанию в compose **`15432`**; у тебя может быть например **`5051`** — как проброшено в `docker-compose`).
- **С своего ПК**, если порт закрыт снаружи: SSH-туннель  
  `ssh -L 5051:127.0.0.1:5051 hl@<IP_hl12>`  
  и в браузере **`http://127.0.0.1:5051`** (подставь свой локальный и удалённый порт).

**Логин в pgAdmin (веб-форма)**

- **Email** и **пароль** из **`.env` на hl12:** **`PGADMIN_DEFAULT_EMAIL`**, **`PGADMIN_DEFAULT_PASSWORD`**.  
- Если не задавали, берите значения из compose/.env на узле БД. На курсе часто свои значения (**не** путать с паролем пользователя `postgres` в БД).

**После входа: привязать PostgreSQL**

1. **Object -> Register -> Server** (вкладка **General:** любое имя).
2. Вкладка **Connection:**
   - **Host name/address:** имя сервиса Postgres в DB-стеке на hl12 (часто `postgresdb`).
   - **Port:** **`5432`** (порт Postgres **внутри** контейнера, не **5433** с хоста).
   - **Maintenance database:** **`postgres`** или твоя база (**`hl3`**).
   - **Username / Password:** как **`POSTGRES_USER`** / **`POSTGRES_PASSWORD`** в **`.env` на hl12** (то же, что для приложения на hl03 в **`SPRING_DATASOURCE_*`**, если одна учётка).

Если регистрация с **`postgresdb`** не проходит — проверь, что **postgres** и **pgadmin** подняты **одним** `docker compose` и оба **Up**.

## 8. Kafka UI с ПК без занятия локального 8080

По методичке [kafka-2026](https://bitbucket.org/zil-courses/hl-module2/src/main/kafka/kafka-2026.md): **Kafka UI** слушает на узле **hl15** (`kafka-2`, менеджер Swarm) на **`127.0.0.1:8080`**. SSH на этот узел — **порт 2315** на **`hlssh.zil.digital`**. Узел **hl14** (2314) — воркер с брокером **kafka-1**; веб-UI там не описан, для UI используй **2315**.

Чтобы не конфликтовать с локальным приложением на **8080**, пробрось UI на другой локальный порт, например **18080**.

**Разово:**

```bash
ssh -p 2315 -L 127.0.0.1:18080:127.0.0.1:8080 hl@hlssh.zil.digital
```

Держи сессию открытой. В браузере: **http://127.0.0.1:18080/** — проверь кластер и свой топик (например **`hl3`** / **`hl03`** по номеру варианта).

**Через `~/.ssh/config`** (отдельная сессия только под Kafka):

```sshconfig
Host hl-kafka
    HostName hlssh.zil.digital
    User hl
    Port 2315
    LocalForward 18080 127.0.0.1:8080
```

Подключение: `ssh hl-kafka`

> В методичке для UI часто дают `-L 8080:127.0.0.1:8080`; **`127.0.0.1` вместо `localhost`** на удалённой стороне важен из‑за IPv6. Локально же можно слушать **`127.0.0.1:18080`** как выше.

## 9. Один SSH на hl03: приложение, Swagger, pgAdmin и Kafka UI — всё с ПК как `localhost`

**Важно:** брокеры Kafka и Kafka UI **не запускаются на hl03** — они на **hl14/hl15**. Но SSH умеет так: после входа на **hl03** сервер **сам** достучится до **внутренних IP** других ВМ. Тогда на ПК достаточно **одной сессии** `ssh -p <ваш_порт_hl03>` с несколькими **`LocalForward`**, и в браузере открываете только **`http://127.0.0.1:…`**, как с pgAdmin и Swagger на hl03.

Идея: подключение идёт на **`hlssh.zil.digital`**, порт из таблицы курса для **вашей** ВМ (пример для варианта 03 — **2303**). Цели проброса:

| Локально на ПК | Куда реально ходит трафик (от имени hl03) |
|----------------|-------------------------------------------|
| **`127.0.0.1:8080`** | сервис на **hl03** (`127.0.0.1:8080`) — CRUD, Swagger |
| **`127.0.0.1:8081`** | доп. сервис на **hl03**, если поднят |
| **`127.0.0.1:<pgadmin>`** | pgAdmin на **hl12** (`10.60.3.9:<порт из compose>`) |
| **`127.0.0.1:18080`** | Kafka UI на **hl15** (`10.60.3.13:8080`) |

Подставь свой порт SSH для hl03 и порт pgAdmin с узла БД (часто **`5051`** или **`15432`** — смотри **`PGADMIN_PUBLISH_PORT`** на hl12).

**Пример одной командой** (без конфликта с локальным 8080 на ПК см. ниже):

```bash
ssh -p 2303 \
  -L 127.0.0.1:8080:127.0.0.1:8080 \
  -L 127.0.0.1:8081:127.0.0.1:8081 \
  -L 127.0.0.1:5051:10.60.3.9:5051 \
  -L 127.0.0.1:18080:10.60.3.13:8080 \
  hl@hlssh.zil.digital
```

Пока сессия открыта:

- Swagger / API: **http://127.0.0.1:8080/swagger-ui.html** (или актуальный путь SpringDoc)
- pgAdmin: **http://127.0.0.1:5051/** (если использовался этот локальный порт и порт на hl12 совпадает)
- Kafka UI: **http://127.0.0.1:18080/**

**Если на ПК уже занят 8080** (локальный Docker/`bootRun`): не привязывайте приложение hl03 к локальному 8080 — выберите другой локальный порт, например **9080**:

```bash
-L 127.0.0.1:9080:127.0.0.1:8080
```

Тогда Swagger на ПК: **http://127.0.0.1:9080/…**

**`~/.ssh/config`** (пример алиаса «всё через hl03»):

```sshconfig
Host hl03-all
    HostName hlssh.zil.digital
    User hl
    Port 2303
    LocalForward 8080 127.0.0.1:8080
    LocalForward 8081 127.0.0.1:8081
    LocalForward 5051 10.60.3.9:5051
    LocalForward 18080 10.60.3.13:8080
```

Если **8080 на ПК занят**, замени первую строку на, например: `LocalForward 9080 127.0.0.1:8080`.

**Оговорки**

1. Должна быть **связность hl03 → hl12 и hl03 → hl15** по внутренней сети (**10.60.3.x**). Если **`18080` не открывается**, проверь с hl03: `curl -sS -o /dev/null -w '%{http_code}\n' http://10.60.3.13:8080` — при необходимости остаётся прямой туннель **§8** через **`-p 2315`**.
2. **Консольный producer/consumer с ПК** к брокерам по **`bootstrap-server hl14.zil/hl15.zil:9094`** — это отдельная история (**advertised listeners**): нужны доп. порты и **`/etc/hosts`**, как в разделе 6 методички [kafka-2026](https://bitbucket.org/zil-courses/hl-module2/src/main/kafka/kafka-2026.md). Для **только веб-UI** достаточно проброса **`18080`** выше.
